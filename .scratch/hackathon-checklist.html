What it takes to win with Safe Globe

A punch list against the H2O.ai Flood Intelligence blueprint, plus a two-track architecture — an offline build for UAT that cannot fail on stage, and a deploy build for judges to poke at afterward.

1 · Make one agent genuinely reason

~1 day

Flood intelligence won partly because its agents call real models for real judgment calls, not scripted scoring. Pick one Safe Globe agent and do the same — don't spread this thin across all five.

01Truth Check → real LLM reasoning

must
  • Replace the rule-based contradiction check in truthCheck.js with an actual LLM callFeed it the statement text + retrieved registry facts, ask it to label each claim Consistent / Unverified / Contradicted with a one-line reason. This is your cheapest path to "real reasoning, not a lookup table."
  • Keep a local fallback path for when the API key is absent or the call times outSame pattern your places.js already uses (curated data → live API → graceful empty state). Reuse it — don't invent a new fallback shape.
  • Log and surface the prompt + raw model output in the case drawerJudges reward visible reasoning. An "Explain this finding" expandable beats a black-box score.

02Forecast → a backtestable method

should
  • Swap the "Beta" placeholder for a simple, stated modelEven an exponential-decay score over historical sanctions-event frequency beats an unexplained percentage. State the method name out loud in the demo.
  • Compute and display one backtest number"On held-out cases, flagged 8 of 10 true escalations" is a sentence the flood project's NeMo Evaluator narrative trained judges to expect. You don't need their tooling, just the number.
→ Don't try to wire all five agents (Sentry, Radar, Web, Tide, Forecast) to real LLM calls under time pressure. One agent done convincingly, narrated well, beats five done shallowly — and it's the one thing a judge will actually probe by clicking around.

2 · Wire one agent to a real external feed

~0.5 day

Flood intelligence polls USGS and NOAA live. Right now every Safe Globe agent reads seed data only — judges will ask "is this calling a real API, or is it fixtures?"

03Pick one real, free, no-auth-friction source

must
  • OpenSanctions API for Sentry (free tier, no key required for light use)Closest match to "41 sanctions lists" framing already in your PRD copy — makes the existing narrative true instead of simulated.
  • Or AISHub / a free AIS feed for Tide, if vessel tracking is the more visual winDark-period detection against a live feed is a strong live-demo beat — "watch this update in real time" plays better on stage than sanctions-list text.
  • Cache responses to disk/SQLite with a TTL, same pattern as sources.js health states (ok / stale / new)So a flaky upstream API during the actual demo window degrades to "stale, last good data" instead of a blank panel.

3 · Two-track architecture

~0.5 day

You already have Cloud Run + Firebase Hosting config and a SQLite/Firestore abstraction in src/db/ — the gap isn't new infrastructure, it's making local and deployed explicitly separate, so a deploy-side failure never touches the demo machine.

Local — UAT & live demo

Single Node process, SQLite file, everything on one machine.

  • npm start, zero cloud dependency
  • External feeds cached with TTL — stale data beats no data
  • Seed-reset script so a bad demo run resets in seconds
  • No load balancer, no autoscaling — nothing extra to fail
Use for: the actual pitch. A dead wifi connection or a cold Cloud Run instance must never be visible on stage.
Deploy — judge follow-up

Firebase Hosting rewrites /api/** and /v1/** to Cloud Run; Cloud Run's managed load balancer fans out across autoscaled instances; Firestore replaces SQLite as shared state.

  • DATABASE_TYPE=firestore flips the existing src/db/ abstraction
  • min-instances: 0 already set — accept the cold-start cost, it's not demo-critical
  • Cloud Build pipeline already wired (cloudbuild.yaml) — push-to-deploy
Use for: the link in your submission form, so judges can click around after the room empties. Never the thing you present from.

4 · Harden what's already built

~0.5 day

You don't need new infrastructure — src/db/index.js already abstracts SQLite vs. Firestore, and Firebase + Cloud Run already gives you hosting and a load balancer for free. The gap is making the two tracks fail independently.

04Demo-day safety net

must
  • A one-command reset script: kill the dev server, delete and reseed data/safe_globe.db, restartIf a live click corrupts demo state mid-pitch, recovery is 10 seconds, not a restart from scratch.
  • Feature-flag any live external API call behind a cached/offline fallback, defaulted on for the local buildConference wifi is the single most common hackathon demo failure. The LLM call for Truth Check and the live feed for Sentry/Tide both need this.
  • Record a 60-second screen capture of the full golden path as literal backupNot glamorous, but it's what separates "technical difficulties, moving on" from a blank stare.

05Deploy track, done once and left alone

should
  • Deploy via cloudbuild.yaml once before submission, confirm /api/health on the live URLA judge following your submission link to a 502 reads worse than not submitting a link at all.
  • Set Cloud Run min-instances: 1 only for the 48h judging window, then back to 0Avoids a cold-start first impression for a judge clicking in; not worth paying for outside that window.
  • Freeze the deploy branch after the pre-submission check — no more pushesA last-minute push that breaks the Cloud Build pipeline during judging is a self-inflicted wound with no upside.

What to cut if time runs short

→ Cut in this order: (1) Forecast backtest number — state the method, skip the number. (2) Second live data source — one real feed is enough, don't chase Tide and Sentry. (3) Deploy-track Firestore migration — SQLite-on-Cloud-Run with a single instance still proves the architecture story, even if it's not "real" multi-instance state. Never cut: the one real LLM call in Truth Check and the demo-day reset script — those are what the whole pitch leans on.
